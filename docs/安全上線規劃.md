# Rhythm in Motion 報名頁｜安全上線規劃書

版本：2026-09-21　適用：`site/`（GitHub Pages）＋ `site/backend/`（Google Apps Script）

## 1. 系統邊界與資料流

```
訪客瀏覽器 ──(HTTPS GET)──▶ GitHub Pages（cn92208.github.io，純靜態，無個資）
     │
     │ 表單 POST（隱藏 iframe，HTTPS）
     ▼
Google Apps Script Web App（執行身分＝主辦帳號，存取權＝所有人）
     │            │
     │            └──▶ MailApp：確認信寄給報名者；摘要通知寄給主辦（不含個資）
     ▼
Google 試算表（僅主辦帳號／指定工作人員可讀）──▶ 活動後 30 日內排程去識別化
```

個資只存在兩個地方：**Google 試算表**與**Gmail 信件副本**。GitHub、GitHub Pages、瀏覽器端都不保存個資。

## 2. 風險盤點與處置

| # | 風險 | 原測試版狀態 | 安全版處置 | 檔案 |
|---|---|---|---|---|
| 1 | 系統錯誤訊息（如「尚未設定指令碼屬性：SPREADSHEET_ID」）直接回傳到瀏覽器 | `error.message` 原樣回傳 | 只回傳欄位驗證錯誤；其他錯誤回「系統暫時無法收件」，細節只留 Apps Script 記錄 | `Code.gs` |
| 2 | 用表單探測某 Email 是否已報名（回應差異成為「預言機」） | 回傳正取／候補、報名編號、`duplicate` 旗標 | 所有成功回應一律通用訊息；結果只寄到該信箱；同 Email 重送＝補寄原確認信、不新增列 | `Code.gs`、`app.js` |
| 3 | 後端 `postMessage(json, "*")` 向任何父視窗廣播結果 | `"*"` | 只送往 `ALLOWED_ORIGIN`（指令碼屬性） | `Code.gs` |
| 4 | 前端接受任何 Google 網域 iframe 的訊息 | 只檢查 origin | 加檢查 `event.source === iframe.contentWindow` 與 payload 型別 | `app.js` |
| 5 | 垃圾報名／用主辦帳號寄信轟炸任意信箱 | 只有蜜罐 | 蜜罐＋最短填表 4 秒＋每小時 40／每日 200 筆上限＋同 Email 去重＋補寄 10 分鐘冷卻＋姓名不可含網址 | `Code.gs` |
| 6 | 同一人多次報名佔滿席次 | 只以 `requestId` 去重 | 同 Email 有效報名只保留一筆 | `Code.gs` |
| 7 | 沒有 CSP，任何被注入的腳本都能執行、任何網域都能當表單目標 | 無 | `<meta http-equiv="Content-Security-Policy">`：`default-src 'none'`、`script-src 'self'`、`style-src 'self'`、`form-action`／`frame-src` 只允許 Google Apps Script | `index.html` |
| 8 | 每位訪客都向 Google Fonts 發請求（訪客 IP、Referer 外流給第三方） | 載入 Google Fonts | 改用系統字型；頁面零第三方資源 | `index.html`、`styles.css` |
| 9 | Referer 帶著頁面網址送到外部連結 | 預設 | `<meta name="referrer" content="no-referrer">` | `index.html` |
| 10 | 共用裝置上送出後個資還留在畫面 | 不清空 | 成功回應後 `form.reset()` 並換新 `requestId` | `app.js` |
| 11 | 主辦通知信含姓名、電話、Email（Gmail 內多一份個資副本） | 含 | 通知信只含狀態、編號、席次；可用 `ORGANIZER_NOTICE=OFF` 關閉 | `Code.gs` |
| 12 | Apps Script 自動偵測的 OAuth 權限過寬 | 未宣告 | `appsscript.json` 明確宣告 3 個最小 scope | `appsscript.json` |
| 13 | Gmail 每日寄信配額用完 → 寄信失敗 → 報名流程中斷 | 未處理 | 先寫入試算表，備註「確認信待補寄」，`resendPendingConfirmations()` 補寄 | `Code.gs` |
| 14 | 試算表公式注入 | 已有 `safeCell_` | 保留並補上 Tab／CR 開頭 | `Code.gs` |
| 15 | 測試掛鉤 `window.RIM_TEST_HOOKS` 留在正式版 | 有 | 移除 | `app.js` |
| 16 | 儲存庫含機密 | 無（已確認：試算表 ID 只在指令碼屬性） | 維持；`endpoint` 與主辦信箱本來就公開，不是機密 | — |

**尚未／無法在此架構內處理的項目**（需特別注意）：

- Apps Script Web App 必須設「所有人」才能接匿名表單，因此**無法限制只有你的網頁能呼叫端點**（任何人都能直接 POST 到 `/exec`）。上表 5、6 的限制是唯一防線；若日後遭大量濫用，可再加 Cloudflare Turnstile（需第三方帳號，本次依你的選擇未採用）。
- 每小時／每日計數使用 `CacheService`，在極端同時送出時可能略微超出上限（非精確計數）。
- GitHub Pages 無法設定 HTTP 回應標頭，因此 CSP 以 `<meta>` 實作；`frame-ancestors`（防止被其他網站嵌入）無法用 `<meta>` 設定，這點屬 GitHub Pages 限制。
- 訪客 IP 仍會被 GitHub（Pages 主機）與 Google（Apps Script）看到，這是使用這兩個服務的固有條件，請在隱私說明中揭露。

## 5. 營運期間規範

- 每週看一次試算表與 Apps Script「執行記錄」，留意 `Rate limit hit`、`Mail quota exhausted`。
- 有「確認信待補寄」備註時，執行 `resendPendingConfirmations()`。
- 額滿後：把 `FORM_STATUS` 改 `CLOSED`、`config.js` 的 `status` 改 `closed`（前端會顯示停止收件）。
- 資料當事人要求查詢／更正／刪除：直接在試算表處理，並回信確認；刪除時連同 Gmail 副本一起刪。
- 匯出試算表（xlsx／csv）到本機時，僅存在加密磁碟並於活動後刪除；不要用通訊軟體傳送名單。
